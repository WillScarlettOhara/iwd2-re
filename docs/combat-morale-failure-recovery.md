# ProcessAI morale failure routing

2026-10-03. Recovered the morale failure entry and shared exit in ProcessAI
(0x72B9A0), using the full tmp_processai_morale.md bundle and PE control flow
at 0x72CA10..0x72CC46 and 0x72CF6B..0x72D073. Existing sprite layout context
is unchanged. CheckMorale runs after the active timer counters advance and
is bypassed for dead sprites. Failed morale skips normal timers, controlled
states and script processing.

On first failure the owner broadcasts CMessageSpriteUpdate, plays SOUND_MORALE
(byte 1 at 0x85BB64) and selects from rand()%100: below 10 PANIC, below 90
RUNAWAYFROMNOINTERRUPT, otherwise BERSERK. Panic/flee set only the base panic
bit here; berserk sets m_berserkActive. Scratch action object selectors remain
unchanged, while specifics, point, strings and flags match the binary. Entry
clears queued actions, requests interruption and enqueues the selected action.
It does not directly drop the path. Further failed checks retain the latch
and action instead of making a new selection.

Recovery clears the latch, broadcasts for the owner, clears actions, queues
DropPath, gets/sets the next action, and clears base and derived panic bits.
This exit is shared by dialogue and normal routing. Normal CheckTimers now
runs after morale recovery. Dialogue pause suppresses normal control/scripts;
its wait countdown, facing and idle messages remain explicitly unrecovered.
ProcessAI remains partial outside this recovered branch.

The network condition uses GetServiceProvider()==SERV_PROV_NULL or local
player ownership, matching +0x96E and +0x104C in the original. Session-open
is a different field and is not substituted.

Added ExecuteAction dispatch for PANIC (24 at 0x8477B2): byte dispatch table
0x72B538 is 0x14 and the 0x729654 case calls Panic at 0x758440, then records
the shared return value. Existing Panic body is unchanged: first execution
queues DropPath/idle, every execution queues RANDOMWALK and returns DONE.

AutoUI moralfailure uses an idle actor in a disposable game process. It
blocks action execution with stone-death state while observing ProcessAI's
selection, requires all three choices within 96 attempts, checks action
retention on the next failed check, then checks recovery clears both panic
bits and emits DropPath. It separately dispatches PANIC at action counts 0
and 1 and checks RANDOMWALK plus the first-call message count. It resets the
test actor's morale/state fields and leaves it idle, but is not a full snapshot
of every ProcessAI side effect. The profile never saves and transactionally
restores save/config paths. Camera centering precedes the actor checks.

These tests observe bounded branches in our build. They do not establish a
full original/recovered differential or all movement generated by morale loss.
